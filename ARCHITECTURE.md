# Architecture

This repository is organized around one source of truth per concern:

| Path | Purpose |
| --- | --- |
| `services/` | Runtime application services. Each service owns its app code, Dockerfile, and Python requirements. |
| `charts/` | Helm charts for GKE deployments. These replace raw Kubernetes manifests for application workloads. |
| `infra/terraform/` | GCP infrastructure: APIs, Artifact Registry, GKE, and deployment service account. |
| `ops/` | Operator-owned tooling configuration such as Jenkins, Airflow DAGs, observability, and database migrations. |
| `ops/observability/` | Prometheus, Grafana, Loki, Tempo, and local/GKE observability configuration. |
| `mlops/` | Model training, feature engineering, BentoML service, and model packaging code. |
| `scripts/` | Thin operational entrypoints used by Makefile, Jenkins, and runbooks. |
| `artifacts/` | Generated build/runtime artifacts. Only the demo model artifact is kept in Git; image URI files and reports are generated by CI. |
| `data/` | Demo training dataset used by the local/GKE MLOps flow. |

## Deployment Model

Application workloads should be deployed through Helm charts under `charts/`. Avoid adding raw Kubernetes YAML under `k8s/` unless it is clearly temporary or documented as a migration aid.

The common service lifecycle is:

```text
service code -> Docker image -> Artifact Registry -> Helm deploy -> smoke test -> observe
```

Kafka and ingestion APIs use the shared versioned envelope in
`contracts/events.py`. `event_id` is the idempotency key, `schema_version`
controls compatibility, and the envelope timestamp records event time.

The `data-streaming` namespace contains the single-broker Kafka KRaft
development cluster and Coinbase WebSocket producer. The broker is deployed as
a StatefulSet with persistent storage, while a Helm hook creates the raw,
validated, and quality topics. This topology is intentionally sized for the
Autopilot development environment; production availability requires multiple
brokers and replication after moving to GKE Standard.

The inference orchestrator owns prediction coordination, alert rule evaluation,
and alert history. These responsibilities share one request lifecycle and do not
need independent scaling or deployment in the current system.

Each successful prediction also emits decision-bound governance telemetry. It
captures the model decision, model identity, latency, available drift evidence,
and operational health. Records form a tamper-evident hash chain on the
orchestrator PVC that can be checked through `GET /governance/integrity`.

## Generated Files

The following are generated and should not be committed:

- `artifacts/**/**/*_image_uri.txt`
- `artifacts/**/training_summary.*`
- `artifacts/**/data_version_manifest.json`
- `.scannerwork/`
- `.venv*/`
- `mlruns/`
- `mlflow.db`
- Terraform state files and `.terraform/`

Jenkins should archive generated reports as build artifacts instead of committing them.
